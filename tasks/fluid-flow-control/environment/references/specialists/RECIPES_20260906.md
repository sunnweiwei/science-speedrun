## Control-limit reconstruction, approximately 10:33 UTC

The older author's explicit Pinball YAML uses max_control=0.5, whereas the current
public asset uses 0.25. The paper's displayed 2D test trajectory ends near zero
drag. A fresh native fixed `[0,-0.375,0.375]` control achieved full-window mean
CD=0.095251, last-half signed mean CD=-0.013680, RMS CL=0.061159 and raw return
-29.77658. It is not a learned policy and negative signed drag is not rewarded as
an improvement: the objective still penalizes absolute drag and lift. This shows
that the broader action range deserves a paper-performance reconstruction trial;
it does not prove that all policies at the smaller limit are fundamentally unable
to match the paper.

The `ppo-scaled` and `ppo-author` 0.25 trials were stopped by the organizer after
their 20k evaluations remained worse than zero control, to free GPUs 0 and 3.
All partial results/source/checkpoints are retained and excluded from full-budget
seed comparisons. Four other 0.25 trials continue. The explicit reallocation record
is `reproduction/control-limit-reallocation-20260906.json`.

New 1,200-step checks at the author-example 0.5 actuator limit use `ppo-narrow`,
`ddpg-slow` and `td3-scaled`, with fresh seed-42 initialization and independent
final/best replays. A persistent queue launches 100k PPO and TD3 trials only after
their corresponding short checks pass, using the tested pilot's frozen source.
The TD3 short check temporarily shares GPU 7 with the 3D diagnostic; its timings
are not dedicated-device throughput measurements. The planned full runs use
dedicated GPUs 0/3. These remain transparent reconstructed settings, not recovered
original figure configurations.

## Cached author observation normalization

`pinball_author.py` now reads the Re100 observation mean/std vectors directly
from the SHA-verified author's `Pinball.environment_default_values[(100,2)]`.
They contain 98 values each, with scales 0.01132–0.03147. The associated default
probe order is y-major `meshgrid`; the previous U_inf-normalized trials used
x-major enumeration. Their coordinates are the same set, but cached statistics
must use their original ordering. `native.py --normalization author` uses the
native `customized` normalization API and stores exact vectors in the protocol.
Frozen evaluation checks preprocessing parity as well as physics and horizon.

The planned `ppo-authornorm` run combines these public defaults, max_control=.5,
and the existing `ppo-author` recipe (Mish/.97/.1). This is a closer public-example
reconstruction, not a recovered final-paper experiment. Queue
`queue-cavity-and-authornorm-20260906.sh` first validates actual cavity training
and fresh replays in the task image on GPU1 after its calibration finishes, then
runs a 1200-control author-normalization Pinball check. Only after that check
passes does it launch 100k controls from the check's frozen source. Existing
Pinball runs are not changed or relabelled as this recipe.
# Public collector-budget clarification — 2026-09-06 12:08 UTC

The released Pinball PPO YAML has `env.num_episodes=500` but the actual collector
uses `total_frames=200000`, with400 frames per update. The environment horizon
is200 controls. Thus the executable public budget is1000 actual episodes/500
collector batches, not500 actual episodes. The paper's plotted500-episode axis
cannot be unambiguously mapped to that incomplete example.

To prioritize performance without silently shortening the released program,
the author-normalized/full-public-optimizer trial now uses200000 controls and
records the explicit name `hg-pinball2d-ppo-authornorm-200k-s42-20260906`.
It starts only after the1200-control artifact check passes. Its learning-rate
annealing horizon also follows200000, matching that YAML. This is a documented
public-source budget reconstruction, not proof of exact final-figure provenance.
Earlier100000-control/500-episode trials remain unchanged and separately labelled.
