## Integration review (2026-09-23, 8× H100 host, Docker, Harbor-style compose)

The integrator built both images, ran the verifier under compose and retrained
the starter: persistence and spatial mean reproduced to 7 decimals, the starter
retrained with the documented recipe on all pools replays at 0.3127 (documented
0.3139), deterministic. Five blocking findings, all fixed in the branch:

| finding | fix |
| --- | --- |
| Bubblewrap never starts under Docker (the network namespace is refused), the uid fallback left `/data` and `/tests` readable, and a package that re-ran the staging code scored 1.0 | the verifier data is mounted under `/private`, root-only, and `/tests` is root-only, so the runner uid can regenerate nothing; Bubblewrap now builds its namespace without the network one where Docker refuses it, the container's `network_mode: none` keeping the package offline |
| neither image built: PEP 668 system Python; the cu130 build needs driver ≥ 580 | `PIP_BREAK_SYSTEM_PACKAGES=1`, base image `2.14.0-cuda12.6-cudnn9-runtime` |
| the dev entrypoint always exited 1 (`sorted(pools)` instead of `.items()`) | the guard is `environment/data/check_agent_mount.py`, unit-tested both ways |
| the documented agent-host recipe exited 1 (upstream step rejected the release heads, fetched `hyp`, `--splits` had no effect on the corpus) | `materialize.py --pools split.json` fetches only pool files and accepts release heads (`release-head` status); a verifier host still refuses them |
| the verifier compose had network access | `network_mode: none` in both overlays |

Minor: `well_cnext/train_dataset.sh` builds The Well's layout from `well-<dataset>/data` with symlinks and runs from a writable directory; the PDEArena conversion needs the pool and held-out shards; the end-to-end tests open pytest's 0700 temporary tree to the runner uid when run as root.

## Verifier hardening (2026-09-24, adversarial pre-review)

A read-only multi-agent review of the verifier, each finding checked by
independent skeptics, found attacks that need no access to the truth at all:

- The grader read `prediction` with the verifier's privileges and followed HDF5
  external links and virtual datasets, so a package could point its output at
  `work/truth/cases/<id>.h5` and score as a perfect forecaster. Package output is
  now read only from regular files whose `prediction` is a plain dataset
  (`score.open_package_h5`); `contract.md` says so.
- A FIFO in place of a prediction blocked the grader forever; a JSON manifest
  that is not an object, or a 900-deep `name`, crashed the verifier; a
  1,500-deep tree in `HOME` crashed the cleanup (`shutil.rmtree` recursion). All
  are now a failed case or reward 0, never a crash.
- In uid mode a call could leave a detached process, files in `/tmp` or the
  runner's home, SysV IPC objects, a runner-owned output next to the rerun's and
  a group-writable sealed package. `isolation.after_uid_call` now kills every
  runner process, gives the output and home back to root (0700), empties every
  runner-writable directory and removes the runner's IPC objects; the seal drops
  write and set-id bits; logs are 0600. `runner_can_reach` counts search
  permission as reach.

`tests/test_verifier_hardening.py` covers each case; every one of them fails or
hangs against the previous verifier, and the whole suite passes as root (uid
mode, 83 tests) and as a regular user.
