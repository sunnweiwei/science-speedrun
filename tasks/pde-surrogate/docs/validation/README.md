# Validation artifacts

Every replay report is a summary written by `evaluation/score.py` (per-dataset
and per-group VRMSE, rollout windows, failures, reward) with its protocol
stated; per-case records are omitted from the committed copies. All numbers are
single runs on one shared A100-40GB between 2026-09-16 and 2026-09-20. Every
number in the task README, `task.toml`, `docs/baseline_score.json` and
`docs/release_validation.json` is in one of these files, and the two summary
scripts below derive the summary records from them.

On 2026-09-22 the corpus family `ape2d/hyp` was removed from the split
(upstream's `hyp.hdf5` is a content copy of `diff.hdf5`). Every record on the
canonical split was recomputed exactly by `drop_duplicate_family.py`: the group
mean is an unweighted mean of per-dataset means, so removing a dataset changes
no other number. Each such record carries a `derivation` block with the values
it had before.

| File | What it records |
| --- | --- |
| `materialize-receipt-2026-09-16.json` | verify-only receipt over every locally downloaded file of the five sources (282 files, 182 GB, 13,212 trajectories): byte size, trajectory count read from the file, status |
| `reduced_is_prefix_of_full.json`, `reduced_vs_full.json` | bytewise check that no reduced-release file is a prefix of its full-release counterpart, with correlations for five files: same parameters, different draws |
| `release_leakage.json` | content check of release `pde-surrogate-split-v2`: every trajectory of `train/` hashed against 580 held-out trajectories, 0 collisions (`check_release_leakage.py`) |
| `trivial_predictors_canonical.json` | spatial-mean, persistence and zero predictors on all 1,085 canonical held-out cases |
| `task_trained_baseline.json` | the task starter (30,000 steps) replayed through the sealed verifier on all canonical cases, with weight hashes and its training provenance (19 of 20 datasets, 2 of 52 PDEArena shards present when it ran) |
| `pdet_zero_shot_<variant>_canonical.json` | released PDE-Transformer checkpoints replayed zero-shot on the 850 canonical corpus cases |
| `pdet_zero_shot_<variant>_transfer.json` | the same checkpoints on the 235 transfer cases (data they never saw) |
| `pdet_zero_shot_mc-s_long_horizon.json` | the small checkpoint on the 270 long-horizon cases (K = 96; secondary protocol) |
| `dpot_<variant>_zero_shot_{canonical,transfer}.json` | released DPOT checkpoints under the task protocol (context padded from 4 to 10 frames, channels in blocks of four) |
| `dpot_<variant>_native_context_pdearena.json` | DPOT with its native ten-frame context, K = 4; not the task protocol, context only |
| `well_cnext_{trl2d,active_matter,pdearena}_from_scratch.json` | CNextU-net trained from scratch with The Well's recipe, one per transfer dataset, replayed on all four groups (per-dataset means embedded) |
| `pdet_finetune_{trl2d,active_matter,pdearena,joint}.json` | released `sc-s` fine-tuned with the paper's recipe per transfer dataset, and once on all three pools jointly; the joint run's negative transfer and the retracted crop explanation |
| `score_bounds.json` | the track's floor (persistence) and ceiling (per-group oracle), every measured package on the normalised scale; generated by `make_score_bounds.py`, which also writes `environment/evaluation/score_bounds.json` |
| `drop_duplicate_family.py`, `make_score_bounds.py`, `check_release_leakage.py` | the scripts that produced the recomputed records, the bounds and the leakage check |
