## Timing boundary definition (`rfd4-a6000-warm-v1` vs `rfd4-paired-program-v1`)

- **`rfd4-a6000-warm-v1` (this directory and `measured_report.py`)**: Every target cohort measures 200 attempts using **warm, batch-amortized GPU execution** (excluding process startup, checkpoint loading, and per-bucket AF3 XLA compilation warmup). Only controller-sealed 200-attempt campaigns measured under this exact warm boundary carry `"profile": "rfd4-a6000-warm-v1"` receipts for `measured_report.py`.
- **`rfd4-paired-program-v1` (`../../evaluation/evaluate_tracks.py` and Harbor `tests/test.sh`)**: Live evaluation of `infer.py` submissions measures whole per-request subprocess generation time alongside **same-GPU paired baselines** (`native-low`, `native-medium`, `native-high`) invoked through the **exact same `infer.py` subprocess boundary**, same target roster, same attempt count, and a dedicated persistent warm AF3 server per GPU. Subprocess-timed `evaluate_tracks.py` runs are never stamped as `rfd4-a6000-warm-v1` and never mixed with 200-attempt warm archive points. Frozen three-budget sweeps (`B/10 = 6 s`, `B/4 = 15 s`, `B = 60 s`) are summarized by [budget_scorecard.py](budget_scorecard.py) ([BUDGET_CURVE.md](BUDGET_CURVE.md)).

From this directory, run `python measured_report.py --output /tmp/rfd4-independent-report` with a fresh output path to render the `rfd4-a6000-warm-v1` panels (`generation.png`, `including-af3.png`). For live paired four-track `infer.py` evaluation and strict Pareto grading, see the [submission contract](../../contract.md).
